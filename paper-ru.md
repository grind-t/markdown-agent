# Markdown DB

Статья описывает модель БД на основе markdown-документа и встроенного LLM-исполнителя запросов.

## Преимущества

- **Простота**: Вся БД хранится в одном markdown-документе и легко читается/редактируется человеком или LLM.
- **Мощная структура**: Markdown задает семантическую и иерархическую структуру для данных, которая позволяет LLM эффективно работать с ними.

## Алгоритм поиска информации

### Терминология

- **Элемент документа**: превью секции или любой блочный элемент markdown, кроме заголовка. Каждый элемент имеет id и, если это превью, полную длину.

### Входные данные

Запрос на естественном языке для поиска информации в БД.

### Шаги

1. **Раскрытие уровня**

Документ раскрывается на один уровень вложенности. На новом уровне показываются превью блоков/секций, уровни выше остаются раскрыты полностью.

2. **Оценка релевантности**

LLM получает документ, раскрытый до уровня `n`, и запрос пользователя. Каждому элементу присваивается оценка `low`/`medium`/`high` по вероятности содержать нужную информацию.

3. **Отсечение нерелевантного**

Элементы с оценкой `low` удаляются и больше не рассматриваются.

4. **Повтор цикла**

Шаги 1-3 повторяются, пока остаются нераскрытые элементы.

5. **Финальный результат**

Когда раскрывать больше нечего, оставшиеся элементы возвращаются как релевантный контекст. Если элементов нет, информации в документе нет.

### Пример полного прохода

Пусть документ БД имеет вид:

```
H1
blockquote_1
H2
paragraph_1
H2
paragraph_2
H1
paragraph_3
```

**Итерация 1**

Раскрытие:
```md
H1
<!-- id: <h1_1>, length: <длина секции> -->
H1
<!-- id: <h1_2>, length: <длина секции> -->
```
Оценка:
```txt
h1_1: high
h1_2: low
```
Отсечение:
```md
H1
<!-- id: <h1_1>, length: <длина секции> -->
```

**Итерация 2**

Раскрытие:
```md
H1
blockquote_1_preview...
<!-- id: <blockquote_1>, length: <длина блока> -->
H2
<!-- id: <h2_1>, length: <длина секции> -->
H2
<!-- id: <h2_2>, length: <длина секции> -->
```
Оценка:
```txt
blockquote_1: low
h2_1: high
h2_2: medium
```
Отсечение:
```md
H1
H2
<!-- id: <h2_1>, length: <длина секции> -->
H2
<!-- id: <h2_2>, length: <длина секции> -->
```

**Итерация 3**

Раскрытие:
```md
H1
H2
paragraph_1_preview...
<!-- id: <paragraph_1>, length: <длина блока> -->
H2
paragraph_2_preview...
<!-- id: <paragraph_2>, length: <длина блока> -->
```
Оценка:
```txt
paragraph_1: high
paragraph_2: medium
```
Отсекать нечего.

**Итерация 4**

Раскрытие:
```md
H1
H2
paragraph_1
<!-- id: <paragraph_1> -->
H2
paragraph_2
<!-- id: <paragraph_2> -->
```
Оценка:
```txt
paragraph_1: high
paragraph_2: high
```
Больше отсекать и раскрывать нечего, финальный результат:
```md
H1
H2
paragraph_1
H2
paragraph_2
```

### Преимущества

- **Высокая точность** - за счет просмотра всех элементов БД риск пропустить нужную информацию низкий.
- **Низкая ресурсоемкость** - не требуется дорогая модель; токены и окно контекста используются эффективно.
